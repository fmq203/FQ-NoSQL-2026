EventFlow — Demo funcional

Usuarios · Eventos · Reservas (SAGA + Chain of Responsibility). Corre 100% contra las APIs reales vía fetch() — necesita docker compose up -d levantado en esta misma máquina.

Infraestructura (bases de datos poliglotas)

Usuarios Service:8001
MongoDB
(usuarios, historial)
⇄
Eventos Service:8002
MongoDB
(eventos, inventario)
⇄
Reservas Service:8003
orquestador SAGA
Redis
(pago + inventario atómico)
PostgreSQL
(event_log / auditoría CQRS)
Reservas → Usuarios (validar usuario) Reservas → Eventos (validar/sincronizar aforo)
Cada servicio tiene su propia base de datos (Database per Service) — Reservas coordina la SAGA llamando a Usuarios y Eventos por HTTP, con reintentos + circuit breaker.

Escenarios de un click

    
Cada botón crea por su cuenta lo que necesita (usuario/evento propios, sin tocar los formularios de arriba) y anima el pipeline marcando exactamente en qué paso de la SAGA ocurre el resultado.

    

    

    

    

  


  

    
Auditoría (PostgreSQL / event_log)

    
Modelo de auditoría CQRS: cada paso de cada SAGA (incluso las que fallan y se compensan) queda como un evento inmutable en PostgreSQL, independiente del modelo operativo en MongoDB. GET /api/reservar/{reserva_id}/audit — reservas-service.
